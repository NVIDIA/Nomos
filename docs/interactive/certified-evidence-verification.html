Certified Evidence Verification

How Nomos turns a trusted executor result into council-readable evidence, and why the council accepts it only after checking the signature against a registered trusted public key.

Current claim The council service verifies Ed25519 evidence and rejects it unless the public key fingerprint is registered and enabled.

Executor certifies result

The executor produces an ExecutionResult and attaches an ExecutionEvidence object. The signed payload includes the writ id, intent hash, council id, command metadata, stdout and stderr hashes, exit code, success flag, and verification stage.

algorithm = ed25519 The council rejects other evidence algorithms.
public_key_hex Must decode to a 32-byte Ed25519 public key.
key_fingerprint Must equal SHA-256(public_key_bytes).
signature Must verify over the canonical payload bytes.
trusted_executor:{fingerprint} Redis lookup by the evidence key fingerprint.
enabled == "1" Disabled executors are rejected even if the signature is valid.
registered public_key_hex Must exactly match the public key embedded in the evidence.

Trust boundary: certified evidence proves that a registered trusted executor signed the exact result being shown. It does not independently prove Kubernetes reality beyond the executor command output and the operational trust placed in the executor key and registry bootstrap path.
